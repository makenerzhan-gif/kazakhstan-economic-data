# project_knowledge/ — what this folder is for

This folder is the **only** part of the repository meant to be synced into the
Claude Project "Экономика Казахстана" (Project Knowledge). It holds curated,
current-state summaries sized for the Project's context (~0.4 MB in total) —
full histories, full metadata and raw archives stay in the repository.

## Files in this folder

- `latest/macro_latest.csv` — one row per series (507): Russian name, agency, frequency,
  unit, first date, number of observations, the latest value, the one before it and the
  value a year earlier. The full history is `data/unified/` in the repository.
- `DATA_CATALOG.md` — counts by agency and frequency, what is not connected, and the known
  problems in the sources (config/source_issues.yaml).
- `DATA_DICTIONARY.md` — per series: unit, frequency, period, the first sentence of the
  methodology. The full record is `metadata/<agency>/<id>.json` in the repository.
- `SOURCES.md` — per-agency source status: API/CSV/XLSX, access barriers.
- `CALENDAR.md` — when the sources the GDP model depends on update next.
- `UPDATE_LOG.md` — recent changelog (older entries: `docs/UPDATE_LOG_ARCHIVE.md`).
- `models/{gravity,bvar,rstar}.md` — the reports of the estimated models (text only; charts
  and CSVs are in `models/` in the repository).

Everything except `UPDATE_LOG.md` and this README is regenerated by
`scripts/build_project_knowledge.py` / `scripts/build_calendar.py` on every pipeline run.
`tests/test_project_knowledge.py` fails if the folder grows past its budget.

## IMPORTANT — syncing is manual

There is no API to write directly into Claude Project Knowledge. The bridge is
GitHub: this pipeline updates the files in this folder automatically (via
`.github/workflows/update.yml`), commits, and pushes — but **nothing after that
is automatic**. Project Knowledge only reflects what's in this folder once a
human clicks **Sync now** inside the Project "Экономика Казахстана" on claude.ai.

**Practical routine:** after any update you care about (or at least every few
days, and always before starting a new analysis session), open the Project →
Project knowledge → **Sync now**. If you skip this, the assistant in that
Project will be working from stale data even though GitHub is current.

## What NOT to expect here

- No raw archives or full histories (see `data/` in the repository — not synced).
- No item-level datasets (trade by partner, GVA by sector, regions, deciles):
  `data/unified/macro_dims_long.csv.gz`, listed in `config/dims.yaml`.
